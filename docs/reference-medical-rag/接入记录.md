复诊准备本身已存在规划、检索评审、带逐字出处的结构化生成和独立核对节点，继续使用现有更严格契约，并接入共享上下文规则；不重复叠加同类模型节点。

medical_qa_annotation属于离线数据标注，simple_qa属于简陋基线，不加入患者在线问答链路。

## 控制与失败兜底

- `RAG_PROMPT_PIPELINE_ENABLED=true`默认启用；仅live模式和支持structured的模型客户端执行新增模型阶段。设为false可恢复原有检索和生成路径。
- 查询规划/资料判断一般8秒，回答核对10秒，单次事实修正25秒，再核对10秒；故障不会无限重试。
- 医院读取、浏览器和总时间仍用原有预算；规划耗时从检索总预算扣除。资料判断最多两次，第二次需要新增资料。普通科普联网最多2条查询、3个页面，总时限30秒。
- 医院多地区请求分别规划，读取时保留后续地区预算，检查仍缺哪些地区；数量不足依旧标为部分资料，不编造、不擅自扩大城市范围。
- 模型提出无效查询或凭空引用source_id会被拒绝；无效查询退回原有计划。所有已取得证据保留。
- 核对服务不可用时保留已有回答，标记unavailable，不能标记为通过；核对明确失败且修正仍未通过时只返回提供资料的原文。
- 当前名单数量修正与新事实核对分别有界，并非无限循环。节点调用次数和预算不会因为模型建议而自动增加。
- 公共查询沿用身份信息过滤；报告仍在原授权范围内处理，直接查已核对字段时不为套流程额外调用模型。

新增模型阶段会增加调用次数与延迟，调用记录按实际HTTP尝试保存，不把离线替身测试记成真实调用。

### 疾病相关医院查询补查

针对名单只剩一家医院的真实运行，已补充“机构发现→逐机构查证”：从实际搜索标题或已读取页面发现机构名称，仅将其作为检索线索，再独立搜索相关科室/服务。每次最多额外8个机构搜索，主查询最多3轮。机构补查当前用于全国或单地区任务，多地区仍分别按原范围查询，不以补查扩大地域。

疾病选院往往需要分别读取医院科室页面，不能套用一张名录页覆盖多家的成本。页面预算按 `max(普通基础预算, min(HOSPITAL_SERVICE_PAGE_LIMIT, 目标下限×2))` 分配，`HOSPITAL_SERVICE_PAGE_LIMIT`默认16、可配1—24。每个机构的首个候选失败或不适用时，可在共享预算中尝试第二个候选。浏览器和总时限仍用原预算，后续主查询保留页面名额，不能无限扩查。

医生排名、最佳医院榜单和就诊攻略只作机构发现线索，不直接证明医院擅长；机构信息只出现在实际网页标题时也可以核对，但医生履历提到的其他医院不应一并算为该页已支持的机构。不会从普通单院页面扩散读取站点导航来凑名单；为后续查询预留页面预算，避免前两轮耗尽预算。

检索词不能擅自引入用户未问的挂号、医保、交通等目标。低覆盖时使用紧凑版介绍，避免长篇扩写一家医院或把建科/更名年份当作诊疗特点。复现证据见 `apps/api/data/official_batch_02/disease-hospital-retrieval-check.json`；新增回归测试见 `test_hospital_service_coverage.py`。

### 公开网页缓存与医院回答兜底

新增独立的公开网页短期缓存，默认有效期24小时、最多128条。写入时验证公开URL与正文摘要标识，过滤带身份或授权参数的地址；不会把患者附件、私人资料或缓存网页自动发布到公共知识库。读取缓存仍需满足本轮地区和疾病条件，保留采集时间和来源身份状态；重复使用不会续期，联网可用时仍会尝试刷新。

排名广告、就诊攻略只能提供机构发现线索，不能作为医院诊疗特点的依据。回答核对明确失败且修正仍失败时，医院查询使用保守的结构化机构列表兜底，只列已取得资料支持的名称与相关科室，不回显广告正文、站点导航或未经支持的排名。核对服务不可用不会被记录为“核对通过”。

最后两轮同题实测“有哪些医院比较擅长处理乳腺癌”均列出8家，按地区、相关科室和服务特点组织，自动事实核对均通过，耗时分别8.3秒、9.5秒。两轮利用了此前读取的公开网页缓存，实时检索仍有上游故障，状态保留为partial；这不是无缓存条件下的检索成功率证明，也不是对医院临床优势的独立认证。本轮相关回归171项通过。复测记录仍保存在上述JSON文件中。
