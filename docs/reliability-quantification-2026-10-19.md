完成60项定向检查，另运行47项相关回归，均通过。60项是场景结果断言，包含同一流程中的多个检查，不是60份独立任务样本，更不能称为生产可靠率100%。只有检查点成本对照调用真实模型，其余使用隔离数据库与可控HTTP/网页返回，不涉及真实医院临床数据。

没有为后三项构造“移除保护”的不安全系统来计算提升百分点。它们属于现有能力验收，非故障率前后下降实验。

## 1. 任务级追踪

HTTP模拟传输产生8次真实客户端尝试，ObservedClient写入8条对应记录，关联run_id、Agent、用途、重试序号、状态、耗时和用量。模拟返回的14 Token是账目测试夹具，不计为真实模型消费。

- 成功返回已知用量：1次尝试。
- 成功但无usage：1次，保留未知，不填0。
- 429后成功：2次，重试序号与失败原因对应。
- 401：1次，记录失败。
- 两次超时：2次，记录provider_timeout。
- 主动取消：1次，记录cancelled。
- 另插入1条未结束记录模拟服务中断，恢复后为interrupted。

检查中未发现测试输入、模拟密钥或原始异常标记泄露到trace元数据。阶段只是显式埋点的begin/end，因此不据此宣称所有业务节点均有开始结束计时。不测人工排障耗时，暂无“定位时间降低X%”证据。

## 2. 检查点恢复与成本对照

使用真实ObservedClient与deepseek-flash，temperature=0、max_tokens=80、thinking沿用当前关闭配置。三个简单中文任务均使用固定输入，两个成功阶段后，在第三阶段HTTP请求之前注入失败。

- 从头重跑：成功执行阶段1、2；失败后再次执行1、2、3，共5次模型请求。
- 检查点恢复：成功执行阶段1、2；重开持久化检查点后复用两阶段，只执行阶段3，共3次模型请求。
- 使用项目实际Checkpoints、checkpoint_call和SQLite LangGraph持久化机制；不是自己写的内存缓存。

| 指标 | 从头重跑 | 检查点恢复 |
|---|---:|---:|
| 阶段工厂调用次数（包含一次注入失败） | 2、2、2 | 1、1、2 |
| 模型HTTP请求 | 5 | 3 |
| 输入Token | 130 | 77 |
| 输出Token | 65 | 38 |
| 总Token | 195 | 115 |
| 用量未知请求 | 0 | 0 |
| 整个试验wall耗时 | 6,328 ms | 4,015 ms |

调用数减少：(5−3)/5=40%。Token减少：(195−115)/195=41.03%。恢复后重复执行已成功阶段由2次变为0次。两组共8次真实模型调用，实际总Token310。

这是非常短的三阶段组件微基准，不包含真实搜索、报告解析或患者写入；失败前没有发出第三次HTTP请求，不能代表已被供应商计费但断连时的情况。两组各跑一次、先从头重跑再检查点组，时延受负载、缓存、网络、持久化开销影响，不宣称稳定提速。不同失败位置、调用成本与缓存可复用范围会改变节约比例。

实际API恢复权限、两次恢复上限、输入变化拒绝、会话消息幂等和重启恢复，另外由13项检查点回归覆盖，不与这次单个成本对照混算。

## 3. 版本和发布

七项逐项检查：

1. 发布准备完成前管理员编辑，旧结果提交被拒，保留新内容。
2. 发布处理中撤回，旧任务不能重新发布。
3. 发布处理中删除，旧任务不能复活资料。
4. 两次基于相同旧revision的写入，后一次冲突，不覆盖赢家。
5. 准备索引过程异常，保持草稿，无半成品索引。
6. 完成状态更新前数据库触发异常，发布内容与状态事务回滚。
7. 合法发布成功，资料与索引同时可用。

核心预期是最终数据库状态正确，而非仅HTTP返回失败。采用注入prepare和SQLite事务，尚未验证MySQL隔离级别、多进程发布竞争或分布式事务。

## 4. 个人资料权限

12类接口操作覆盖：记录列表、报告列表、对话、任务、删除报告/记录/对象、取消任务、后台观测、执行链路、知识库和巡检。

- 未登录：12项均401。
- 其他用户：8项私有操作均404，4项后台操作均403。
- 普通所有者访问后台：4项均403。
- 同一用户把一个复诊对象的报告挂到另一个对象：1项404。
- 总计29项预期拒绝均符合，响应不含测试私有标记。
- 合法所有者报告读取成功，防止“所有请求一律拒绝”的假通过。
- 额外核对受测报告、记录、对象未被非法删除。

首轮量化脚本使用带连字符的测试用户名，不符合登录校验，已登录角色实际未登录，初始13/31检查不用于权限结论。修正测试账号并强制断言登录成功后，只重跑权限组，31/31通过。原始记录保留，不修改生产权限逻辑或把401改判为越权拦截。

未测试所有上传/下载端点、全部更新字段、浏览器会话攻击、提示词注入或实际模型外传路径。结果不是“绝无泄露”。

## 5. 公共知识更新巡检

文本分类四例：首次建立观察基线、相同文本、仅空白变化、实际正文变化，4/4符合预期。样本太少，不给真实语义识别率、精确率或召回率。

另八项：

- 发现网页变化不自动覆盖已发布正文。
- 读取失败不推进基线，错误元数据不泄露原始异常。
- 失败任务可重试成功。
- 暂不采用保留已发布内容。
- 人工采用后进入草稿、revision递增且不携旧检索索引。
- 旧正文归档。
- 过期快照采用被拒。
- 显式重新发布后资料恢复published状态。

网页读取与索引准备为受控替身；最后一项测状态提交，不测真实向量供应商或管理员表单校验。真实API日期缺失拒绝重新发布、域名变化、编辑/撤回/删除冲突、重启恢复等由12项巡检回归另行覆盖。
