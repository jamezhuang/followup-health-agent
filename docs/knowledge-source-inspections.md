# 公共资料更新巡检

入口：admin 账户 → 后台管理 → 公共知识库 → 资料更新巡检。

## 使用流程

1. 选择带原始来源链接的已发布公共资料，每批最多20份，提交手动巡检。
2. 首次读取建立网页观察基线，显示“首次采集，待核对”。知识库可能只存节选，首次采集不等于发现来源更新。
3. 后续成功读取与上一次成功网页快照比较。比较会规范空白，仍可能受导航、时间戳影响；文本变化不等于事实变化。
4. 查看新旧文本、提交时知识库节选、来源等级与日期。管理员可暂不采用，或采用为草稿。
5. 采用会归档旧内容、移除旧检索索引并暂停该资料发布。核对正文、机构、适用范围和日期后，通过已有审核发布流程重新建立索引。无发布日期时留空，不继承旧日期。

## 边界与保护

- 仅管理员可操作；不读取个人报告，不自动搜索新网址，不自动发布，不含定时调度。
- 复用现有网页安全读取和浏览器回退；需启用 live 模式和外部读取。跨来源域名跳转拒绝采用，来源等级不会因抓取成功而自动提升。
- 读取失败不改变基线或已发布资料。任务最多尝试3次，重启中断标记失败，排队任务恢复执行。
- 资料已编辑、撤回或删除时，旧任务不能采用；已有更新的不同网页快照时，旧快照不能采用。
- 暂不采用只处理审核状态。之后网页不变的巡检仍可采用，避免错过之前未采用的内容。
- 队列最多20个活跃任务，当前为单进程工作队列；多进程部署、定时巡检和第三方平台集成仍需后续实现。
- 列表保留最近50条任务供查看，详情保留快照；现阶段未做自动归档清理或全文差异高亮。

## 接口与验证

`GET/POST /v2/admin/knowledge-inspections`：列表、批量提交。
`GET /v2/admin/knowledge-inspections/{id}`：快照详情。
`POST /v2/admin/knowledge-inspections/{id}/retry`：失败重试。
`POST /v2/admin/knowledge-inspections/{id}/review`：apply / dismiss。
运行观测和精确任务查询支持 inspection 类型，巡检本身不调用生成模型。

后端回归覆盖快照比较、读取失败、过期版本、审核、权限、重启恢复、日期缺失和重新发布边界；浏览器覆盖对比及人工采用交互。测试使用注入网页读取器与合成资料，不代表真实医院网站抓取成功率。
