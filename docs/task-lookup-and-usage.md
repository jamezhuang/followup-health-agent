# 任务精确定位与单次消耗

入口：管理员登录 → 后台管理 → 运行观测 → 任务精确定位与消耗。

粘贴完整任务ID，选择自动识别或对话/入库/发布类型后查询。最近知识失败列表的“定位此任务”会自动填写完整ID、查询并滚动到结果。不是按ID前缀搜索，不受最近100条任务窗口限制；同ID匹配多种任务时，自动识别返回409，需要明确类型。

## 可查看和执行

- 任务类型、完整ID、状态、阶段、尝试次数、错误码及分块进度。
- 模型请求次数（含失败重试）、已知Token、用量未知次数、模型请求累计耗时、耗时未知次数。
- 任务生命周期耗时：自创建至最后更新，执行中取当前时间，包含排队和重试等待。
- 对话任务可进入执行链路；失败的入库/发布任务可直接重试，沿用原最多3次、队列容量和文档版本检查。
- 对话执行链路也附带该任务的请求和Token汇总。

## 归属和口径

新发布任务的模型调用使用 `knowledge-publication-{task_id}` 归集，跨重试仍关联同一发布任务。旧版 `knowledge-{document_id}` 记录不能唯一划分到某次发布，不分摊，不计入该任务消耗；存在这些记录时界面明确提示当前数字不是完整历史消耗。调用明细中新的发布请求可直接定位对应任务；旧文档/独立检索请求不会被错误当作对话任务打开。

当前文件入库解析不调用模型。查不到可精确归属的调用不能据此推断整个文档从未消耗模型额度。

未知Token不按0计入，已知Token合计只是已知部分。累计模型请求耗时包含并行与重试，不能当作用户等待时长；任务生命周期也不等于有效处理时长。没有供应商计费配置，未换算金额。调用聚合按精确ID读取全部相关请求，不套用最近10000次全局调用窗口。

## 接口和隐私

GET `/v2/admin/tasks/{id}?kind=auto|run|import|publication`，仅管理员可用。不存在返回404，类型冲突409，非法参数422。返回允许的元数据，不返回患者对象、问题、答案、文件名、原件、引文或原始上游错误。已有执行链路仍沿用原管理员权限。

## 验证

74项相关后端测试通过，包含历史任务定位、拒绝前缀误匹配、类型冲突、权限、隐私、未知用量、重试统计、新发布ID归属与旧文档调用隔离；已有入库、发布和引用回归一并通过。

前端类型检查通过；6个浏览器场景覆盖精确查询/重试/错误清空、观测汇总跳转、后台滚动、批量上传、发布检索撤回、引用展示。测试为临时数据库和合成调用，无真实计费。
