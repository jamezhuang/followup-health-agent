# 正式公共回答引用校验

日期：2026-10-19。

## 使用范围

已接入公共科普和医院服务的模型回答，有公共资料时使用结构化回答协议。普通聊天、无来源回答、个人报告与复诊摘要不受这次协议变更影响。登记官网入口等确定性回答沿用原有来源检查。

生产配置 PUBLIC_CITATIONS_ENABLED 默认 true；false 可回退到原回答协议。融合排序权重未改变，默认仍为1。

## 工作流

1. 将候选的完整来源ID映射成 S1、S2 等短编号，同时保留来源等级、适用范围、日期等元数据。编号不能由模型自行关联到网址。
2. 模型返回 content、answer_kind（full/partial/insufficient）和 citations（source_id、逐字quote）。部分回答只引用已支持部分；纯不足或追问允许空引用。
3. 程序核对来源编号精确存在、quote是该来源原文子串、正文含对应编号、正文短编号有引用记录；禁止模型为引用编号自带链接。
4. 引用不合格最多修复一次；两次仍失败则返回引用未核实提示，不展示那些结论与引用。结构化服务不可用则回退既有回答及事实核验路径，标记 unavailable，不声称引用校验通过。
5. 继续执行既有语义事实检查。事实检查若修改正文，重新运行引用检查，避免“改了答案却沿用旧引用”。
6. 核验完成后，程序将短编号映射回完整来源ID和真实URL；前端只有 passed/repaired 状态才渲染可点击编号及“查看引用原文”。未知编号与未通过引用不作为来源链接显示。

这套确定性检查只证明出处、逐字摘录及编号关联有效，不证明引文足以支持整条结论，也不证明完整性或医学正确性。语义检查仍保留。纯不足答复不为凑引用而追加旁支资料。

## 验证

- 67项相关后端测试通过：完整/部分/不足回答、空引用、截短ID、伪造quote、一次修复、修复上限、事实修正后引用失效、模型自带引用链接、服务不可用回退，以及入库发布回归。
- 前端类型检查通过；3项浏览器流程通过，包含真实组件中的引用点击、展开原文、隐藏未通过引用，以及批量入库发布回归。
- 真实模型正式 chat 函数测试使用独立库和合成公开资料，没有访问外部网站或患者资料。最终报告：`apps/api/data/local_lifecycle_eval/production-citations-02cb14a12b/report.json`。
- 该轮4题的编号/引文校验均通过；严格回答类型预期为3/4。余号不足题输出了有依据的预约渠道说明，模型标为partial，脚本预期insufficient，因此保留该项失败；不将其改写成全通过。明确要求仅说明不足的题返回无引用不足答复。
- 较早两轮报告保留在 production-citations-be4c6e4305、production-citations-80213906fb。真实调用样本很少，模型自核不能作为独立临床验证。

## 后续

补充独立人工确认的真实脱敏问题，区分“答不了核心问题但给了相关信息”和“已回答一部分请求”；进一步验证长文、多来源冲突及引用修复的token/延迟预算。不要把格式校验通过率写成事实正确率。
