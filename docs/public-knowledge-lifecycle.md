# 公共知识入库闭环

本次实现聚焦本地知识，不新增外部搜索供应商或抓取策略。

## 使用方式

管理员进入工作台 → 后台管理 → 公共知识库。

“批量上传文件”支持 Ctrl / Shift 多选，每批最多20个、单文件最多8MB。前端逐文件提交独立任务，显示提交进度及失败文件；单个提交失败不会阻断后续文件。重复文件复用已有任务。批量提交完毕后，从任务列表逐项打开资料核对，不自动发布。

1. 上传 TXT、MD、DOCX 或文本 PDF（非空、最大 8MB）。文件先进入持久化任务队列，后台解析成功后创建草稿；原件保存到 SQLite 的 `knowledge_files` 表。刷新页面后可从“最近入库任务”查看结果并打开草稿。
2. 核对正文，补充来源链接、发布机构、日期和使用依据，可设置适用地区及动态名录快照类型。保存草稿。
3. 点击“预览分块”检查原文位置及片段。草稿不参与公共检索。
4. 审核发布。发布时保存分块索引；live 模式且配置 embedding 凭据时生成向量，否则保存可用于 BM25 的索引。来源资料仍需人工核实，点击发布不意味着已完成临床审核。
5. 在“本地知识试检索”输入问题，检查召回片段与原文。试检索只使用本地已发布资料，不调用外部搜索；配置适配时可能调用外部 embedding 服务生成查询向量。
6. 编辑会回到草稿并清除旧索引，需要重新发布。撤回后不参与新的公共检索。上传原件保持不变，可下载核对；删除资料同步删除原件。

上传以文件 SHA-256 检测重复。异步入口复用同文件任务，旧同步入口重复提交返回 409。原件与草稿在同一事务写入；解析失败不创建资料。正文手动粘贴及内容相似但字节不同的文件尚无语义去重。

## 数据与检索

- 文档、来源、状态与版本：现有 `entities` 表，公共知识 owner=`*`、kind=`knowledge`。
- 上传原件：`knowledge_files`，仅管理员可访问；不混入个人档案。
- `retrieval_index`：随文档持久化的分块、定位信息和向量，带内容指纹与文档版本；与当前内容不一致时不复用。
- 沿用现有 SQLite JSON 存储，不是单独的向量数据库；当前语料规模下检索仍需扫描候选。
- 公共问答与管理员试检索复用分块和 BM25/向量融合算法；公共问答另有查询改写与证据筛选，因此试检索只验证召回，不等于最终回答质量。
- 仅模型名称匹配的已存向量用于公共向量检索。向量查询失败回退 BM25；发布时向量不完整则不发布。取消任务继续传播，不被普通失败回退吞掉。
- 旧资料兼容动态切块；需要重新发布才会生成新格式持久化索引。本次没有批量修改或重新发布现有资料。

## 接口

均要求管理员身份：

新增 POST `/v2/admin/knowledge-imports` 提交任务（202），GET 同路径查询最近50项任务，POST `/v2/admin/knowledge-imports/{id}/retry` 重试失败任务。任务查询不返回文件字节；下表同步上传接口作为兼容入口保留。

| 接口                                     | 用途                               |
| ---------------------------------------- | ---------------------------------- |
| POST `/v2/admin/knowledge/import`        | 上传、解析、留存原件并创建草稿     |
| GET `/v2/admin/knowledge/{id}/original`  | 下载上传原件                       |
| GET `/v2/admin/knowledge/{id}/chunks`    | 分块预览                           |
| POST `/v2/admin/knowledge/search`        | 本地已发布知识试检索，参数 `query` |
| POST/PUT `/v2/admin/knowledge[/{id}]`    | 沿用草稿创建与编辑                 |
| POST `/v2/admin/knowledge/{id}/publish`  | 校验来源、生成索引并发布           |
| POST `/v2/admin/knowledge/{id}/withdraw` | 撤回                               |

发布、编辑、撤回沿用 revision 乐观锁。来源与试检索返回不暴露向量和父段落内部数据。

## 后续工作

原件/元数据历史版本归档；向量配置版本（模型、维度、服务）更严格的指纹；更多规模下的独立索引与查询性能；基于冻结数据的召回效果对照。

新增异步文件入库：SQLite 持久化排队、单个后台消费者处理、阶段状态查询、失败手动重试、同字节文件复用任务。最多20个排队或处理中的任务，单任务最多尝试3次；完成后清除队列文件副本，原件保留在正式文件表。草稿、原件与任务完成状态在同一事务提交。

服务启动将遗留 processing 任务标记为 worker_interrupted，管理员可重试；queued 任务自动继续。当前仅支持单 API 进程，未实现多实例租约，不应使用多 worker 同时运行此队列。失败文件留存在任务中用于重试，后续需增加清理策略。

审核发布与向量化现已改为异步：管理页面提交 POST `/v2/admin/knowledge/{id}/publish-task`，返回202；GET `/v2/admin/knowledge-publications` 查询阶段和片段进度；POST `/v2/admin/knowledge-publications/{id}/retry` 手动重试。原同步发布接口作为兼容入口保留。已有回答与历史引用不会因资料撤回而被抹除。

发布队列同样以SQLite持久化、单API进程运行，最多20个待处理任务、每任务最多尝试3次、一次处理上限180秒。同一文档同一目标版本复用任务；重启后排队任务继续、中断任务标为失败。生成过程不写入半成品索引，发布内容和任务完成状态在一个事务提交。编辑、撤回或删除后旧任务版本检查失败，不覆盖新内容，需重新审核最新版本。

无embedding配置时保存关键词检索索引；配置向量服务时才进行向量化。生成失败不悄悄改成无向量发布，管理员可检查配置后重试。页面保留约五条任务的可视高度，其余记录使用右侧滚动条查看。

异步发布阶段验证：66项相关后端测试通过，覆盖处理中编辑/撤回/删除、部分失败不发布、事务回滚、恢复重试、去重、鉴权与向量进度；两项浏览器流程通过，TypeScript检查通过。真实模型质量与费用不由这些合成测试证明。

本阶段验证：59项相关后端测试通过（包含持久化恢复、重试上限、队列上限、事务回滚和权限）；浏览器验收扩展覆盖刷新页面后查询任务并重新打开草稿；前端类型检查通过。均使用临时数据库和合成资料。
