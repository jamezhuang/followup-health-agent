# 两个主分支与上下文机制

## 入口和操作

新入口意图只有 `daily` 与 `followup`。医院查询和公共医学检索是日常咨询内部的工具选择，并非第三、第四个主分支。

| 用户需求 | 主分支 | 内部处理 |
| --- | --- | --- |
| 日常交流、健康知识、癌症或化疗原理 | daily | 一般回答或公共医学检索 |
| 地区医院名单、科室、地址、挂号、费用、疾病或手术方向选院 | daily | 医院检索及来源核对 |
| 个人报告问答、历次比较 | followup | 当前授权报告及已确认记录 |
| 要求将报告归档 | followup/archive | 引导附件现有核对确认流程，不通过聊天静默入档 |
| 调取已保存复诊信息 | followup/retrieve | 当前账号、当前对象、已确认资料；临时附件不冒充已保存资料 |
| 明确要求复诊清单 | followup/prepare | 有资料时按资料整理；无资料时给一般准备清单，不强制先建对象 |

上传报告默认仅供对话，不能因为提到复查就自动生成复诊清单。日常咨询不会因用户已有档案而读取其私人报告。保留旧对话的历史意图字段兼容，不批量改写历史回答。

## 医院需求理解

当前问题优先；显式的新地区、疾病或要求覆盖历史条件。“哪个／那个医院”不是机构名。仅有“化疗去哪家医院”且缺少地区和疾病时先补必要条件，不猜癌种或默认全国排名。

模型从原话抽取公共诊疗方向，服务端验证其确为原文短语且不含身份或数值。疾病/损伤与治疗方式分别保留。检索规划可给相关科室与共享原词根的同义/上位检索表达，用于发现网页；原始方向保留在首条查询，最多三轮，不把相关科室提示当作该院已开展服务的证据。

字面过滤未通过的正文可在既有总预算内最多接受两轮语义核对；每轮最多八份正文。需要实际机构名称、地区和诊疗原文；请求治疗方式时还必须有该治疗的原文引文。服务端再次检查来源ID、名称及引文确实存在。排名广告、导航和科普页面不能凭这个过程变成医院诊疗证明。省市归属与医学同义表达仍有模型判断误差，后续回答事实核对不能视为临床认证。证据不足时保留缺口，不为了四家或更多数量造答案。

## 上下文怎样记住对话

1. 完整对话存于按账号和对象隔离的SQLite记录；模型自身不会因为一次聊天永久更新权重。
2. 每轮重新装配上下文：当前问题、近期消息、较早消息的节选，以及保留用户原话和来源的更正、限制、决定与待确认事项。当前实现主要是确定性抽取与节选，并非无限容量的语义记忆。
3. 随预算收紧，近期消息数量从12条收缩到8条或4条；采用UTF-8上界估算，不冒充供应商精确token数。关键信息仍超预算时要求明确范围，而非悄悄丢弃全部限制。
4. 医院任务继承最近仍有效的公开任务状态；中间切换到无关任务后不跨过去强行继承。日常公共查询排除此前个人报告回答作为公共事实的来源。
5. 报告附件ID在当前账号、对象和会话内重新核验；已确认字段优先于识别正文。临时识别、患者自述、历史报告和当前医嘱不混作同一种事实。
6. 资料检索与生成完成后检查回答是否答当前问题、是否换了医院/地区/日期、是否新增无依据评价。失败只做有界修正，不无限重试。

因此，Transformer是底层模型处理本次输入的机制；对话存储、选择历史、任务状态、资料授权、检索和答案核对是应用层机制。两者共同工作，仍不能保证完全不跑偏。后续已接入持久化阶段检查点和管理员有界恢复，具体边界见[管理员故障定位与检查点恢复](管理员故障定位与检查点恢复.md)；并非所有内部子节点都能独立恢复。

## 验证

真实分类记录：`apps/api/data/official_batch_02/two-branch-routing-live-check.json`。癌症、化疗、广东医院名录和湖南韧带撕裂手术选院均进入日常分支；这份记录证明分类与规划，不等同于所有问题都有足够实时来源。

复杂选院实际检索记录：`apps/api/data/official_batch_02/hunan-ligament-consultation-check.json`，保留来源数量、拒绝/读取统计与实际回答，不只展示成功案例。

本轮湖南韧带手术例最终为 `insufficient_evidence`、0份可用来源：方向和查询条件保留成功，但多页网络/解析失败，取得的正文仍不足以支持选院名单。尚未实现这个复杂问题的满意回答，不能将分类验证通过等同于检索链路已全面解决。

自动测试：`test_two_branch_routing.py` 覆盖两分支模式、口语院名、疾病与手术条件继承、语义引文核验、当前对象归档信息调取及聊天不自动保存。相关V2与检索回归359项通过，前端类型检查通过。尝试全目录测试时，旧模块缺少jieba，部分旧知识库/评测数据缺失，另有旧模块测试失败，因此不宣称全项目所有测试通过。
