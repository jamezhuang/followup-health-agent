# 管理员故障定位与检查点恢复

日期：2026-10-18。入口：后台管理 → 运行观测 → 最近对话任务 → 链路“查看”。

## 能看到什么

运行是否完成与答案是否有用分别记录。答复结果包括已回答、部分回答、未能回答、执行故障、待补充/确认和执行中。它们是执行记录的规则诊断，不是医学正确性认证。

诊断显示定位阶段、固定原因码、搜索候选及去重/筛除数量、普通/浏览器读取、正文成功/失败、语义核对补回、最终可用来源与停止原因。网页已成功读取但全部不适用于问题时归为证据筛选，不误报全部网页读取失败。执行链路保留实际搜索供应商的顺序、候选数、HTTP状态和切换/重试记录。

检查点表显示阶段、状态、阶段执行次数、最近耗时及检查点标识。一次搜索步骤可能包含多个供应商HTTP请求，实际尝试见执行链路；阶段次数不等于供应商HTTP次数。管理员接口不返回问题、患者正文、模型提示词或检查点状态内容。

## 如何恢复

符合条件的新任务显示“从检查点恢复 / 重试失败步骤”。只有管理员可以触发；普通账号仍只能读取自己的对话和资料。后端按任务原始归属恢复，管理员不能通过请求指定其他患者或替换任务内容。

每个任务最多手动恢复两次，单阶段最多执行三次。每次恢复给失败步骤新的有界执行机会，成功步骤按原请求参数复用。医院每轮原有搜索、页面、浏览器和时间预算仍适用；人工恢复的额外执行机会明确计数，不声称所有恢复共享最初的75秒预算。需要补充资料、用户禁止联网、主动取消或已正常回答的任务不提供恢复。

恢复保留原任务ID和原始输入；同一轮回答以run_id幂等替换，不重复追加问答。保存报告仍走现有核对确认和原子归档流程，检查点重放不会自动确认归档。

恢复前重新检查原对话、后续消息、对象版本、选择资料版本和已读取的记录/文档快照。原资料删除、变化、对象改变、对话已有后续变化或超过24小时则拒绝，要求重新核对提问。并发恢复通过运行状态与版本更新阻止。

## 持久化实现与边界

采用LangGraph `AsyncSqliteSaver`（`langgraph-checkpoint-sqlite==3.1.2`）。线程标识由账号归属、任务ID和阶段输入摘要共同生成。每个阶段使用一个持久化阶段图，保存输入、节点执行和完成状态；恢复时从该阶段的未完成节点继续。成功的公共工具调用还保存必要的候选、页面、来源关联账本增量，恢复后不会只有候选ID而丢失来源上下文。原始状态以JSON存储，不开启pickle。

当前阶段边界：意图识别、查询规划、公共/医院检索、逐次搜索/来源核验/网页读取/链接发现、回答生成与核对、报告问答及复诊处理。复诊内部已有图暂以“复诊资料处理”作为一个恢复单元，不宣称每个内部模型子节点都能独立恢复。当前提供故障恢复，不提供任意修改检查点、单步调试或任意时间点回退。

业务元数据在原SQLite的run_inputs/run_steps表；LangGraph状态在业务数据库旁的`.checkpoints.sqlite3`。状态可能含授权历史和资料，属于私人业务数据，不通过管理员诊断接口导出。有效期24小时；启动及每小时清理过期状态，删除对话/对象时清理对应检查点。旧任务没有原始输入检查点，仍能看旧链路，但不能追溯生成可恢复状态。

正常关闭和突发退出分别保留或恢复为中断任务；不会把服务重启当成用户主动取消。任务不会在启动后自动重放，管理员需要明确点击恢复。

## 验证与使用提醒

`tests/test_run_checkpoints.py` 覆盖跨实例恢复、正常关机后恢复、只重试失败网页而复用成功搜索、候选/来源账本恢复、权限限制、恢复上限、对话幂等、资料/后续对话变动拒绝、过期清理及答复结果分类。

`e2e/run-recovery.spec.ts` 在隔离合成服务中注入首次回答失败，验证后台定位到回答阶段，恢复后意图只执行一次、回答执行两次，最终仅一轮对话。没有把替身测试当作真实供应商恢复成功率；搜索403、反爬或额度问题仍需上游恢复或可用备用通道，检查点不能使不可访问网页自动变得可读。

实现参考：[LangGraph持久化](https://docs.langchain.com/oss/python/langgraph/persistence)、[检查点及故障恢复](https://docs.langchain.com/oss/python/langgraph/checkpointers)。

本次验证：372项相关V2/检索回归通过；前端类型检查通过；管理员恢复与档案归属两项隔离浏览器验收通过。旧版模块的全目录依赖/数据缺失问题未在本次任务中处理，不将这些结果表述为全项目所有测试通过。
