# 统一任务协调与职责审计

## 原有决策重叠

| 节点 | 原有职责及问题 | 当前处理 |
| --- | --- | --- |
| 入口意图识别 | 模型识别后还被关键词分流覆盖 | 成功的模型决策保留；规则只作模型不可用时的降级 |
| 医院规划 | 再次用正则提取医院、地区、服务主题 | 复用入口主协调 Agent 的公开任务计划，原规划作为兼容和降级 |
| 查询改写 | 再调用模型，且必须保留最初提取的名称及地区 | 有有效共享计划时跳过此模型调用和词片段白名单；无有效计划保留原流程 |
| 服务分类 | 服务大类查询词覆盖具体地址、交通问题 | 仅在没有明确主题时用分类补充查询词 |
| 检索工具 | 搜索、读取、浏览器及实际链接发现 | 继续作为工具，接受共享子任务查询；私有档案不传给公共搜索 |
| 检索充分性评审 | 判断当前证据能否回答 | 保留，针对同一任务上下文反馈；已有证据保留，未完成任务优先搜索 |
| 回答事实核对 | 核对机构、数字、来源、时效及任务覆盖 | 保留独立核对，不额外重新分类 |
| 个人档案权限和归档确认 | 程序控制 | 继续由程序控制，不交给模型放宽 |

这次合并的是决策职责和状态，并不把整个应用变成一个无限自主循环。普通医疗科普及个人复诊流程继续保留既有工具和权限。

## 共享任务状态

入口 JSON 的 `public_task_plan` 包含理解后的请求、原始机构名、待核实检索别名、地区及其来源、逐项问题和查询、依赖关系、缺失信息。服务标签可以扩展，不作为工具可用性的枚举门槛。

检索侧不再单独调用查询改写。运行中按子任务已有正文覆盖优先搜索未完成事项；结束时将任务问题、依赖、候选正文 ID 和状态写入 `query_plan.tasks`，供结果诊断保留。

`evidence_found` 仅指找到相关主题的候选正文，不能解释为该问题已充分核实。例如出现“院区”二字不足以证明院区总数；最终仍由充分性评审和事实核对判断。依赖关系用于记录任务顺序，不强制把所有检索串行化；搜索可提前发现交通资料，回答仍须对应同一院区和地址。

## 验证与保留边界

- 地区、等级、公立等明确条件不因子查询简化而删除，最终资料仍按现有适用范围检查。
- 机构别名只是候选，保留原始名称；不把模型纠错直接当作官方身份认证。别名须接近原名称或已出现在请求/有效上下文；不接受任意新医院。
- 查询及问题检查个人身份、病历号等敏感内容，依赖必须引用当前任务内更早的任务，不允许重复 ID、循环或悬空依赖。
- 任务 JSON 无效或模型不可用时可降级，不把错误文本写入用户回答。降级可能仍使用原有查询改写，不能宣称所有路径都只调用一次模型。
- 当前检索总轮数、读取页数、超时和来源核对预算继续生效；任务较多可能只完成部分，不承诺完整覆盖。
- 未知服务标签保留其原始问题和查询，当前本地关键词覆盖器不能验证它时标记未解决，由语义评审及回答处理，不能自动视为充分。

## 官网追问及历史范围恢复

当前问题明确指定医院时优先采用该机构，不能因共享计划校验失败而改回上一轮地区名单。官网、网址作为独立任务识别；对话前缀不应成为医院名称的一部分。多个历史医院且仅说“他的官网”时仍需澄清，不猜测对象。

计划校验记录 `plan_validation` 原因码，包括缺少计划、结构错误、无依据机构名、地区错误、明确地区冲突、无安全且对应目标的任务、重复或无效依赖。无依据的模型推测地区可被移除并记录修复，不能让这个非必要字段导致正确的医院任务整体丢失。

已核对官网登记可提供对应入口，登记本身不证明本轮访问成功或业务信息最新。检索优先读取该确切入口，并记录 `official_entry_checks`；读取失败仍可如实提供有登记依据的官网链接。分院域名不能代替已登记的本部官网。

开放服务标签通过任务问题与查询映射到可识别的覆盖主题，例如 `official_website` 和 `website` 均可由“官网网址”语义线索参与覆盖判断，避免资料已找到但状态因标签不同而误报。未知语义仍保持未解决。

事实核对发现当前明确医院与检索上下文不一致时，先返回 `retrieval_required`，执行层清除旧范围重新检索并生成回答一次；不在错误资料上反复文字修补，也不无限循环。

官网回归覆盖 `tests/test_hospital_website_recovery.py`；真实验证可执行 `python -X utf8 scripts/check_shared_task_plan.py --website`，会产生真实调用，公开结果写入忽略的 `.cache/website-recovery-live.json`。

## 科普检索相关性与失败兜底

公开知识的 BM25 排名只是候选召回，不能代表资料与问题有关。充分性评审返回的 `source_ids` 用于实际筛选，即使整体资料不足也保留相关部分；与问题无关的权威资料不传给回答生成。联网新增正文后重新评审，更新最终来源列表和充分性结果。

普通科普回答在核验及修正均失败时返回简短的资料不足说明，不转而倾倒排名最前的指南原文。只有用户明确要求原文时才允许摘录；摘录也须与当前问题有词项对应。科普短问题先直接回答，不主动扩展具体药品、剂量、疗程或停药天数。

对应测试为 `tests/test_public_relevance.py`。可执行 `python -X utf8 scripts/check_public_answer.py` 进行真实公开资料检索及回答核对；不读取患者档案，会产生真实调用，结果位于忽略的 `.cache/public-answer-live.json`。

## 验证入口

`tests/test_shared_task_plan.py` 覆盖错别字、院区误认地区、三个子问题、复用计划跳过改写、部分证据保留、敏感查询拒绝、无效依赖和未知服务标签。

可运行 `python -X utf8 scripts/check_shared_task_plan.py` 进行公开问题的真实模型和联网检索检查，会产生真实调用；输出保存在忽略的 `.cache/shared-task-plan-live.json`，不使用患者档案。测试和现场检索结果分别记录，模拟通过不代表真实外网资料一定可获取。
